# 整本工资工作簿导入与月度核算排除绩效

**Status:** ready-for-agent

**建立日期：** 2026-10-10

**阶段：** 需求设计完成，尚未实现。三项实施拆分及完整流程验收已由用户确认。

## Problem Statement

HR 的月度来源是一整本工资工作簿，其中同时包含花名册、考勤、工资明细和辅助工作表。当前必须拆成员工、考勤等固定模板分别上传，且原表的跨表引用不能直接导入，重复准备文件容易错期或遗漏员工。

绩效由独立流程计算，月度工资不需要处理绩效。当前系统却仍要求正式员工的月度绩效系数，并在试算、输入版本校验、核算就绪、激励、确认、更正和导出中使用绩效。只隐藏导入入口会留下金额和流程错误。

## Solution

### 已确认的业务范围

- 一次选择目标公司及工资期间，一次上传整本 `.xlsx`；内部先处理花名册，再处理全公司考勤。
- 绩效不属于整本月度导入或月度核算；不读取工资明细中的绩效系数，不计算、倒推或默认补齐绩效金额。
- 新增员工的任职、薪资、base 城市和银行卡生效日取所选期间月初与入职日的较晚者；纠错仍使用原任务绑定的期间，不能改为纠错当天。
- 已有员工继续按合法证件号码静默跳过花名册导入，不覆盖资料或生效信息；考勤使用该员工本期有效资料校验。缺历史生效资料时明确报错，不自动补写已有员工历史。
- 旧确认结果只读保留；此后新试算与新更正统一使用不含绩效的月度口径，包括对旧含绩效批次发起的新更正。

### 工作表识别和数据来源

首版针对用户提供工作簿的固定结构适配，不提供任意字段映射。

| 工作表 | 用途 | 接收范围 |
| --- | --- | --- |
| 花名册 | 员工资料输入 | 证件号码、姓名、主体、部门、岗位、职级、入转离职日期、固定薪资、base 城市推导及银行卡等必需资料 |
| 考勤表 | 月度考勤输入 | 身份匹配、应出勤、迟到早退分钟、未补卡次数、无薪及有薪假；沿用 19 列事实语义 |
| 法定假日列表 | 必要的工作日计算来源 | 仅在应出勤公式依赖时读取放假及补班日期，不建立独立日历管理功能 |
| 工资表明细、最低工资标准、增减项异动表、工资条、代发及报税等 | 原文件追溯 | 不写入月度工资输入，不采用薪资合计、扣款、绩效、增减项或税额 |

工资明细或辅助页存在空值、不支持的公式、外部链接，不得阻断无依赖的合法花名册与考勤事实。外部链接包可以保留在原文件中，但不得发起网络访问或执行宏。

### 用户流程与结果

1. 在现有导入中心选择“整本导入”及已建立的工资期间，展示全公司范围。
2. 上传后识别来源结构及文件声明的月份。缺必需工作表、表头不匹配或声明月份不一致时，整份拒绝，不写员工、部门、任职、考勤或工资批次；不得静默切换月份。
3. 保存通过校验的员工资料，再重新取得本期全公司任职范围，保存合法考勤。仅有效考勤行自动补建草稿正常批次。
4. 展示花名册和考勤各自的处理行数、成功数、失败数，以及考勤按主体的归集结果。花名册既有员工的跳过不计入处理行数，不新增重复提示或跳过计数。
5. 按工作表、原始行号、字段及单元格位置显示全部失败原因。缺员工或本期任职的考勤标为依赖未就绪，仍属于未保存的失败行。
6. 修正花名册失败行后，只重验其依赖的失败考勤；修正考勤后只保存该失败行。已成功的资料和考勤不重写、不重复入账。
7. 历史任务只读查看，支持原文件下载、各子批次结果及进入本期核算。上传不会自动试算、计算激励、确认或导出。

结构失败不进入部分成功流程；可定位的行级业务失败允许正确行先保存。某个员工资料失败只阻断依赖该员工的考勤，不阻断其他合法员工。既有员工的花名册行被跳过时，合法考勤仍可以保存。

### 原表公式、本机引擎与有效记录

- 保留原文件、原表达式、解析值、来源位置和修正前后值；导入结果位置必须指向原工作表，不显示内部转换模板的位置。
- 多工作表读取及固定字段映射仍由 Adapter 负责；跨表、查找、日期和数组等必要公式交给经过验收的本机引擎，不再自行扩展成 VLOOKUP、IFS、NETWORKDAYS 等复杂函数的语义解释器。
- 推荐先验证稳定版 LibreOffice/UNO 强制重算，`formulas` 为轻量 Python 备选；不同时集成多个引擎或静默切换结果。最终采用者必须通过本例必要公式、陈旧缓存、文本标识、异常输入与目标部署环境测试，不能仅依据函数名单选型。
- 只将花名册、考勤有效输入及必要依赖的结果用于导入。优先限定临时副本的求值范围；若引擎的强制计算会机械求值其他单元格，其结果不成为工资、绩效、扣款或税务输入，无关错误不得阻断合法事实。
- 关联必须唯一，以完整证件号码复核身份、姓名、主体。即使引擎执行了原表通配符查找，也不能将模糊或多重匹配当作员工匹配成功；公式结果仍须通过文本和归属校验。
- 对工作日合计，按原式实际起止日期、放假及补班依赖求值，不读取上传文件旧缓存、不硬编码 21 天、不用自然日替代工作日。试用期与转正工作日拆分不作为固定薪资折算依据。
- 在任务独立临时副本上应用修正、显式强制重新计算，之后才读取本次结果；普通文件转换成功、非空缓存或打开文件成功都不算重算证据。记录引擎及版本、输入/修正版本和求值来源，保留原文件不变。
- 进程只在本机运行，禁用宏、外部链接更新及外部文件/网络型公式；引擎失败、超时或异常退出应明确报错，不读取旧输出或自动降级成缓存/零值。必要依赖无法可靠求值时定位失败行，允许用户填核实后的事实值。
- 正式产品必须在实际后端部署环境提供受验收、版本固定的运行时，不依赖 Codex 私有工具、本机桌面 Excel 或开发版 LibreOffice。引擎不可用时无业务写入；不要求用户手工拆表或整表粘贴为值才走正常路径。
- 辅助日历缺失或日期非法时，只阻断真正依赖它的输入；考勤应出勤为合法常量且不依赖日历时不要求日历。
- 只统计和遍历含导入数据的有效行；格式延伸、空白行和原表序号不作为员工记录。身份证缺失但有其他输入的行属于错误行，不能作为空行忽略。示例中的百万行工作表尺寸不得触发虚假的超行数拒绝或百万空行扫描。
- 沿用文件 20MB、每个输入工作表最多 5,000 条有效记录的边界；辅助页与金额计算列不计入导入记录数。

### 月度不含绩效的算薪和历史规则

- 月度准备状态只检查员工本期资料、考勤及有效规则。缺绩效、空绩效、非法绩效或试用期绩效记录均不构成月度核算阻断。
- 新月度应发为固定薪资减考勤扣款加考勤激励；未扣个税金额再减个人社保、公积金。公司成本仍按既有缴费规则计算；不把绩效基数合并为固定薪资，也不改变固定薪资、入离职自然日折算或 P7 免罚规则。
- 新月度指纹不纳入绩效事实、绩效导入修订号或与月度无关的绩效资料变化；考勤、固定薪资、任职、缴费城市、账户、规则及激励等相关变更仍使试算失效。
- 新口径必须参与试算版本校验，旧未确认试算须重新试算和查看结果，不得复用旧含绩效试算来确认。单纯更换软件口径不改写或自动作废旧确认结果；确认后到锁定前的既有输入变更保护仍须有效。
- 历史已确认、锁定、导出的金额和快照不批量重算或清零；历史台账及历史结果导出继续按当时快照解释。
- 新更正沿用原确认快照中的员工范围、固定薪资及缴费规则，只允许修正考勤，排除原快照中的绩效收入，并重新生成整批新版本。旧版本直到新版本按受控流程锁定后才被替代。
- 更正页面须明确提示“本次按月度不含绩效口径计算，原绩效金额不计入新结果”，并可对照旧结果。历史绩效记录和原快照仍保留，不能删除来源以实现排除绩效。
- 四类导出识别结果口径：新结果不在当月薪资标准、应发、未扣个税金额或成本中夹带绩效基数或金额。原模板的绩效区域保留结构，显示本月不适用并留空；旧结果仍展示其历史绩效信息。不把未知绩效基数伪造成已知零值。
- 月度工作台、首页、批次准备和新更正入口移除绩效待办、进度及编辑控件。既有绩效资料和历史查询保持可追溯；独立绩效计算功能不在本需求内。

## User Stories

1. 作为 HR，我希望一次上传原工资工作簿，以免每月重复拆花名册和考勤。
2. 作为 HR，我希望任务始终绑定所选月份，以免文件内容让系统静默改期。
3. 作为 HR，我希望系统识别固定工作表和必要来源，以免其他工资、税务和输出页变成计算输入。
4. 作为 HR，我希望原表必要引用可以安全解析，以免必须先把整本公式转为值。
5. 作为 HR，我希望新员工先保存再匹配考勤，以便同一上传能完成资料和月度输入。
6. 作为 HR，我希望新增员工按所选期间初始化生效信息，以便历史月份具有正确的本期资料。
7. 作为 HR，我希望已存在员工不被旧表覆盖，以便保留当前已维护资料。
8. 作为 HR，我希望合法行先保存、依赖失败行单独列出，以便一个员工的错误不阻断所有人。
9. 作为 HR，我希望看到原工作表中的错误位置和全部失败原因，以便直接核对源数据。
10. 作为 HR，我希望修正员工资料后关联失败考勤能够重验，以免重复上传整份文件。
11. 作为 HR，我希望重复提交返回同一任务、成功行不重复保存，以免产生重复工资输入。
12. 作为 HR，我希望历史原文件与修正记录只读可查，以便解释月度事实的来源。
13. 作为 HR，我希望没有月度绩效记录也能试算、计算激励和确认，以便绩效的独立流程不阻断固定工资。
14. 作为 HR，我希望月度绩效数据变化不影响当前试算，以免无关数据导致反复核对。
15. 作为 HR，我希望旧确认工资按原快照保留，以便历史金额仍可解释。
16. 作为 HR，我希望旧批次的新更正也明确排除绩效，以便后续统一遵循新月度口径。
17. 作为 HR，我希望四类导出与月度新结果一致，以免计算已排除绩效但导出又加回绩效。
18. 作为 HR，我希望现有员工及考勤单项导入继续可用，以便只需补充单项数据时不上传整本。

## Implementation Decisions

- 分为“月度核算与历史兼容”“整本输入接收”“依赖纠错与追溯”三个可独立验证的 Module。复用已有员工和考勤领域校验、保存及原始记录；不从前端分别调用两个会独立提交的上传端点来冒充一个整本任务。
- Excel Adapter 负责固定结构识别、有效行读取、本机引擎调用和事实映射；service 负责公司与期间锁、事务、顺序、子批次及重验；domain 负责不含绩效的纯计算；API 负责输入与错误映射。引擎不是工资计算模块，金额仍遵循 Decimal 文本契约。
- 引擎求值在业务写入事务前完成，受超时和资源约束，不长时间占用公司/期间数据库锁；写入及纠错时仍重新校验当前任职、唯一性和批次状态。只封装一个已选引擎所需的调用，不预建多引擎插件框架。技术选型依据见同 feature 的引擎评估，WB02 先完成强制重算与部署验证再接入。
- 对外增加整本上传、读取任务结果/历史及失败行修正的 Interface，参数是目标公司、已建立的工资期间、文件和必要修正值。不能要求选择主体或工资批次，不能提供覆盖已入库数据的开关。
- 持久化一份整本导入记录，关联员工与考勤子批次，保存公司、期间、文件哈希、原文件、结构版本及汇总；使用公司、期间、文件内容保证重复请求幂等。只增本功能必需的关联，不建通用任务队列、后台调度或导入框架。
- 原文件按整本任务保存，子批次和既有原文件下载入口必须能回溯此来源。员工资料的重复检测仍以公司和证件号码为准，考勤仍以公司本期员工事实拒绝覆盖。
- 在完整结构和月份验证后再执行资料与事实写入。预期行级失败允许部分成功；未预期的数据库或计算异常回滚本次事务。父记录与已成功子结果不能丢失关联；已有保存函数的事务职责需收敛到整本用例，而不是嵌套调用会提交的 HTTP 用例。
- 由新确认快照记录月度计算口径，指纹同时校验口径；旧确认快照不改写。旧未确认试算通过新口径指纹变更失效，新更正明确采用不含绩效口径。
- 现有员工薪酬及正式工资快照的绩效基数为非空字段，且资料导入会校验绩效字段。实现时将不参与月度的绩效信息从必需校验中隔离；允许缺失基数留空，并用必要的新增迁移与 DTO 调整承载，保留原已有值，不用默认零或猜测回填兼容旧 schema。
- 新增迁移只改变必要的可空约束或整本来源关联，保留原金额非负、精度、文本标识及历史不可变约束；不改写初始迁移。回退不能删除新来源或空值记录后假装无数据损失，须明确可审查的回退限制。
- 保留既有单项员工、19 列考勤及 v2/v1 导入兼容。单项员工导入仍沿用导入当天的生效口径；所选期间初始化仅用于新整本入口，两个入口在页面上明确说明。绩效历史及旧接口不作为月度输入依赖，不新增独立绩效业务。
- 页面复用现有导入中心及批次详情职责，以花名册/考勤分别展示结果、按主体展示考勤归集；沿用紧凑表格、只读历史和窄屏内部滚动。实施前同步原型、清单和交付说明。

## Testing Decisions

验收边界已由用户确认：以真实整本上传及纠错 Interface、专用 PostgreSQL 测试库和试算到四类导出的业务结果为主；页面测试补充交互。测试外部行为，不镜像内部函数或只断言有某个新字段。

| 范围 | 必须证明的行为 |
| --- | --- |
| 固定结构 Adapter 与本机引擎 | 示例必要跨表引用、查找、日期、IFS 数组及工作日正确；故意写入陈旧缓存仍重算；格式延伸不冒充记录；原位置正确；无关错误不阻断；必要外部依赖拒绝且不触发网络/宏；引擎不可用、超时或崩溃无业务写入 |
| 新月度核算 | 无绩效、旧绩效存在或变更时金额与就绪状态一致；固定工资、考勤、缴费及激励变化仍失效；旧未确认试算无法确认 |
| 历史与更正 | 旧确认金额及导出不变；对旧含绩效结果的新更正排除绩效、明示差异，整批锁定后才切换有效版本 |
| 新增员工初始化 | 月初在入职前/后两种情况都取正确生效日；银行卡和城市同步生效；失败行修正仍绑定原期间；已有员工不被覆盖或自动回填 |
| 整本用例 | 结构/月份不匹配无业务写入；员工先保存再刷新本期范围；同文件多主体归集；合法考勤才补草稿；数据库异常回滚；确认/锁定/无效批次不可写 |
| 幂等与重验 | 并发同文件只创建一任务且不重复员工/考勤；修正员工后只重验依赖失败行；重复修正成功行拒绝；变更文件不覆盖本期已有事实 |
| 页面 | 默认、加载、空、错误、部分成功、全部成功、纠错、禁用、只读历史及桌面/390px 状态；月度流程无绩效待办，结果显示来源位置和生效口径 |
| 四类导出 | 新口径不加回绩效基数或金额；旧快照保留；模板结构、未扣个税标识和未知税额留空规则保持 |

使用现有纯计算、Excel 解析、导入 API 集成、版本校验、更正与导出回归的测试模式。合成工作簿不得含真实身份证、工资、银行卡或公司信息；真实示例只用于本机结构与必要表达式核对，未经用户要求不得向业务库写入。数据库测试限定 `paylite_test` 且显式允许重置。

每项实施完成后执行改动范围静态与格式检查、分层及编译检查、相应后端/前端测试和生产构建。最后验收“整本输入→依赖纠错→试算→激励→确认→锁定→四类导出→旧批次的新更正→有效版本查询”，保持上月激励来源和全公司就绪规则。

## Out of Scope

- 独立绩效计算、绩效发放或绩效补发产品流程。
- 任意 Excel 自定义映射、自建通用公式引擎、多引擎插件平台、宏执行、远程重算、工作日历管理。
- 工资增减项、业绩提成、经济补偿金、工时和税额的新增导入；不自动将这些值变成独立补发。
- 自动覆盖既有员工、自动修补既有员工历史任职/薪酬、完整员工历史档案。
- 自动试算、确认、锁定或导出；跨月更正上月扣款并联动已确认激励。
- 批量修改旧确认工资、删除绩效历史、重写初始迁移、引入后台任务平台。

## Further Notes

- 本需求独立于已完成的 19 列考勤精简修复；保留当前未提交改动作为实施基线，不能回退旧修复。
- 用户已明确绩效独立、历史初始化日期，以及旧结果只读但新更正排除绩效；不再把这些当作待收敛问题。

- 本机示例核对：20 个工作表；花名册含 28 个已命名列（含序号），考勤为 56 列；花名册与工资明细的声明尺寸接近百万行，但 XML 的实际内容远少于声明尺寸；工作簿含外部链接包。首版不能要求只含两个工作表，不能遍历声明尺寸，也不能因辅助页链接拒绝整份文件。
