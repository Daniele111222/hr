# 01：月度核算排除绩效并保留旧结果

**What to build：** HR 不导入月度绩效也能完成固定工资试算、激励、确认和四类导出；旧确认结果保留原金额，对旧批次发起的新更正排除绩效。

**Blocked by：** 无本 feature 前置票；既有普通试算、确认、更正及导出功能作为代码基线。

**Status:** ready-for-agent

**需求来源：** [整本导入与月度不含绩效规格](../spec.md)。

## 验收标准

- [ ] 月度流程、工作台和首页不显示绩效待办、就绪阻断或新更正中的绩效编辑；旧绩效资料与历史仍可只读查询。
- [ ] 无绩效、空/非法绩效或试用期绩效记录均不阻断新月度试算、激励、确认、锁定及导出，月度金额不读取绩效。
- [ ] 月度金额由固定薪资、考勤、激励和既有缴费规则生成，不把绩效基数转成固定薪资；文本标识、Decimal、两位小数和未扣个税标识不变。
- [ ] 绩效事实、导入状态或相关绩效资料变化不影响新月度指纹；固定薪资、考勤、规则、任职、城市、账户和激励变化仍使旧试算失效。
- [ ] 新计算口径参与版本校验，旧未确认试算须重算并查看后才能确认；旧确认结果不因口径上线自动改写。
- [ ] 旧台账和旧结果导出沿用快照；新更正沿用原固定薪资和规则、只修正考勤、明确排除绩效并显示口径变化，锁定后才受控替代。
- [ ] 四类导出新结果不加回绩效，原绩效区域保留结构且标识不适用；旧结果仍按历史快照解释。
- [ ] 员工资料及新工资快照中的绩效字段不成为月度必填或隐性校验门槛；缺失留空，既有值保留，不用零值伪造。必要的可空迁移新增 revision/SQL，DTO 与调用方同步，回退不静默丢数据。
- [ ] 专用测试库覆盖完整核算及旧结果更正；页面交互测试、生产构建、改动范围静态/格式/分层/编译检查通过并记录实际证据。

## 实施边界

不删除绩效表、旧记录或历史接口，不开发独立绩效产品，不改工资折算、考勤激励来源、社保公积金规则。单项员工导入的生效日仍按原约定处理。
