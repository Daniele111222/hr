# 03：整本导入的依赖纠错、幂等与追溯

**What to build：** HR 在同一次整本任务中修正员工或考勤失败行，系统只重验其依赖的失败输入；刷新、重复请求和历史查看都能准确追溯同一任务，不重复入账。

**Blocked by：** [02：整本上传花名册与考勤并支持历史初始化](02-workbook-import.md)。

**Status:** ready-for-agent

**需求来源：** [整本导入与月度不含绩效规格](../spec.md)。

## 验收标准

- [ ] 展示失败所属工作表、原始行号、字段/单元格和全部错误，依赖未就绪的考勤明确标为未保存；不将其视为成功或遗漏。
- [ ] 修正花名册失败行沿用任务期间及正确生效日，在隔离副本应用修正并通过同一个引擎强制重算必要源字段，结果对应本次修正版本；通过后只重验依赖该员工且尚未保存的考勤，成功事实不重写。
- [ ] 修正考勤只编辑有效事实；可以填核实值替换无法求值的输入公式，来源金额和辅助列只读；原始数据和原表达式不被修正覆盖。
- [ ] 员工或考勤已成功的行不重复写入，重复修正成功行拒绝；考勤已有本期事实不可通过换文件、修正身份或重试静默覆盖。
- [ ] 失败行重验按本期当前任职和批次状态校验；批次已确认/锁定、归属不唯一或确认后扩张期间时仍拒绝，不自动建立补发或更正。
- [ ] 原文件、解析值、修正前后值、依赖来源、各行主体与工资批次及修正结果可追溯；历史详情只读，刷新后仍可查看同一任务。
- [ ] 按公司、期间和内容去重，覆盖并发上传、重复文件和并发重复纠错；校验来源月份不匹配时拒绝错期，不返回其他期间的任务。
- [ ] 任务及子结果汇总随纠错更新，成功与失败统计准确，既有员工跳过仍不暴露为重复提示；变更有效考勤使相关试算失效。
- [ ] 页面纠错、错误反馈、只读历史、成功结果和窄屏交互均有测试；原工作表位置在上传、纠错和数据库重新读取后保持一致。
- [ ] 专用测试库与实际前端完成整本输入→依赖纠错→试算→激励→确认→锁定→四类导出→旧批次新更正→有效版本查询的最终验收；区分合成测试和真实工资人工对账。

## 实施边界

只重验失败输入，不新增自动修补既有员工历史或成功行覆盖功能；不增加全表重跑、后台队列、跨月激励联动或绩效流程。
