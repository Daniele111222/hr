# 轻算薪 PayLite — 项目决策与产品记忆

> 来源会话：`sess_9860b1f0-a51c-4cfd-8e74-b95c1d00eae1`（2026-08-31）
> 状态：路线已定，代码尚未起步；技术栈等待最终确认。

## 1. 选定路线

**路线 C**：轻量、本地 / 自部署优先的中国算薪工具。

定位：**Excel 增强器 + 算薪核对器**。

导入花名册和月度变动 Excel → 批量计算个税（累计预扣法）+ 按城市五险一金 → 输出工资条 / 银行代发表 / 申报辅助表，并提供「手工 Excel 对照、差异标红」的核对模式。

工作名：**轻算薪（PayLite）**。

## 2. 目标用户

中小企业 HR：

- 规模约 5–300 人
- Windows + Excel 使用习惯
- 无专职 IT 部门

## 3. 产品边界（明确不做）

- 不做一体化 HRMS（考勤 / 招聘 / 绩效等）
- 不接个税申报接口，只导出申报辅助格式
- 数据不出本机：本地存储、无账号、无云同步

## 4. 核心壁垒

按年份版本化的「城市社保基数 + 个税规则」开源数据包。

- 暂名：`payroll-rules-cn`
- 存储：JSON
- 每条规则带来源链接和生效日期
- 固定维护节点：每年 7 月社保基数调整、每年 1 月扣除标准调整

## 5. 功能优先级

| 优先级 | 内容 |
| --- | --- |
| P0 | 花名册 Excel 导入导出；规则数据包；月度批量算薪（累计预扣法个税 + 按城市五险一金）；工资条 / 银行代发 CSV / 申报辅助表输出；对照核对模式（与手算 Excel 差异标红，差异化卖点） |
| P1 | 年终奖两计税方式对比；不足月折算；政策补差 |
| P2 | 多公司主体；年度报表 |

## 6. 数据模型（SQLite）

| 表 | 说明 |
| --- | --- |
| `employee` | 员工，含年度累计状态 |
| `payroll_period` | 薪资期间，状态：草稿 → 试算 → 锁定 |
| `payslip` | 工资条 |
| `adjustment` | 调整项 |
| `rule_*` | 规则数据包相关表 |

## 7. 里程碑

| 里程碑 | 内容 |
| --- | --- |
| M1 | 算薪引擎库 + 规则数据包（先覆盖北京、上海、广州、深圳、杭州）+ 黄金测试；纯 Python 包可独立开源 |
| M2 | Excel 导入 → 批量算某月 → 导出工资条 / 代发表 |
| M3 | 核对器模式（差异标红 + 原因定位）、年终奖对比 |
| M4 | 打包 exe、历史回算、政策补差 |

黄金测试：用 51社保 / 东方财富等公开计算器的真实案例做对照集。

## 8. 技术栈（拟定，待确认）

尚未拍板，当前建议：

- Python 3.12 + FastAPI（Excel 生态：openpyxl / pandas）
- SQLite 本地单文件
- React + Ant Design（若更熟 Vue 可换 Element Plus；不建议纯浏览器版）
- PyInstaller 打包单 exe，双击启动开浏览器

可复用的中国个税参考实现：

- `theajack/salary`（JS 累计预扣）
- `linglu/geshui`（Python 累计预扣）
- `beijing-salary-calc`（Vue 3）

## 9. 市场调研要点

商业市场饱和：薪人薪事、i人事、Moka、2号人事部、北森、用友 / 金蝶 ERP，以及国际的 Gusto / Rippling / ADP / Deel。

开源 HRMS 均无中国税制本地化：

- Frappe HRMS（约 8.7k stars，GPL-3.0，Python，极活跃）
- Horilla（Django）
- OrangeHRM / IceHrm / Sentrifugo（停滞或 open-core）

关键政策背景：

- 累计预扣法逐月变化
- 社保基数每年 7 月调整（北京 2025：7162–35811 元）
- 多地用工属地政策
