## 产品范围

系统只服务一个目标公司，但目标公司有多个国内工资归属主体。系统以员工当前主档、最新固定薪酬和绩效部分基数为基础，每月导入考勤表和绩效表，生成月度工资结果，并填充四个既有 Excel 模板：

1. `人工成本表-模版.xlsx`
2. `代发工资模板.xlsx`
3. `工资表模板.xlsx`
4. `正常工资薪金所得_模板.xls`

当前不做：

- 个税计算
- 个税申报接口
- 多公司
- 复杂用户权限
- 项目工时
- 人工成本表中的项目工时部分
- 主体或员工特殊社保/公积金比例覆盖

个税相关字段没有外部来源时留空，并在导出报告中提示；系统不把这些字段设计成个税计算字段。

## 已确认的核心规则

### 薪酬

```text
实际月薪 = 固定薪酬 + 绩效部分基数 × 绩效系数
```

- 绩效表直接提供最终绩效系数。
- 绩效系数必须是非负数，不设固定上限。
- 绩效系数缺失时直接报错，该员工不生成正式工资结果。
- 员工主档只维护当前最新固定薪酬和绩效部分基数。
- 工资结果必须保存计算时的员工、主体、部门、职级、固定薪酬、绩效基数、base 地、银行卡等快照。

### 工资期间和批次

- 工资期间按自然月。
- 工资结果主粒度：员工 + 主体 + 工资期间 + 发放批次。
- 每个主体每月一个正常工资批次。
- 补发和其他发放使用独立批次。
- 按期间汇总导出时，独立批次合并到员工期间总结果。
- 状态流转：草稿 → 试算 → 确认 → 锁定 → 导出。
- 锁定后不能直接编辑，只能通过更正批次生成新版本。
- 期间汇总取最新有效版本。
- 同一主体、工资期间、员工和批次类型重复导入时直接拒绝；明确发起更正后才生成新批次。

### 考勤

- 应出勤天数由考勤表提供；节假日、调休和加班由考勤表先处理。
- 每日标准工时为 8 小时。
- 迟到和早退按分钟计量并使用同一公式：

```text
固定薪酬 ÷ 当月应出勤天数 ÷ 8 × 异常分钟数 ÷ 60
```

- 请假只记录天数。
- 有薪/无薪只适用于请假：有薪假不扣固定薪酬，无薪假按天数折算。
- 忘打卡每次扣 30 元，补卡后免扣。
- 同日多个异常由考勤表先合并。
- 考勤表提供事实，系统统一重算扣款，不直接信任表内扣款金额。
- P7 及以上员工不参与任何考勤罚款，也不参与考勤激励分钱。
- 所有考勤扣款必须保留异常类型、原始事实、计算依据和来源。
- 工资项目和最终结果保留 2 位小数并四舍五入，中间计算保留高精度。

### 考勤激励

从 2026 年 7 月起按月复用以下规则：

- 使用上月所有主体锁定后的考勤扣款总额作为本月激励池。
- 本月参与者必须有考勤记录、无迟到、早退、忘打卡、请假，并且是正式、已转正且职级低于 P7 的员工。
- 分钱不区分职级；符合条件的员工按人数平均分配。
- 按符合条件人数平均分配。
- 保留 2 位小数，除不尽的尾差给排序最后一名符合条件员工。
- 激励计入应发和实发，不计入社保、公积金基数。
- 无符合条件员工时不生成激励，但必须产生提示。
- 工资项目名称为“考勤激励”。

### 社保和公积金

- 员工的 `base` 地决定适用城市规则。
- 社保和公积金均以固定薪酬作为缴费基数。
- 绩效、考勤扣款和考勤激励不计入缴费基数。
- 社保各险种和公积金使用城市规则中的比例、基数上下限。
- 第一版不允许主体或员工覆盖城市规则。
- 入职、离职或转正发生在月中时，社保和公积金按城市规则整月缴费。
- 工资本身仍按生效日期分段，固定薪酬按自然日折算。
- 城市规则缺失或过期时阻止计算和导出。
- 结果只保存系统计算值，不设置人工结果对照字段。

### 组织和员工

- 只有一个 `company`。
- `subject` 是工资归属主体，第一版不区分法律类型。
- `department` 使用共用部门体系；不同主体可以有同名部门，并支持上下级关系。
- 员工身份证号码是业务唯一标识且不可修改。
- `employee` 只保存当前资料，不建立员工资料历史版本。
- 月中主体、部门、职位和薪酬变化按生效日期处理；历史工资记录保存快照。
- 查询维度包括工资期间、主体、部门、员工和导入批次；默认按主体和工资期间汇总。

## 已确认的技术栈与运行方式

- 后端：Python 3.13 + FastAPI + Uvicorn + Pydantic v2。
- 数据库：PostgreSQL，使用 SQLAlchemy 2.x、Alembic 和 psycopg 3；数据库运行在本机。
- 前端：React + TypeScript + Vite + Ant Design。
- Excel：使用 `openpyxl` 处理 `.xlsx`；旧式 `.xls` 税务模板先转换为 `.xlsx`。
- 当前以本地网页端运行，浏览器访问本机 Web 服务；暂不实现 PyInstaller、Windows 安装包或单个 EXE。

## 设计要求

1. 先检查仓库当前结构、依赖、已有迁移方式和测试方式，再决定文件位置和实现方式。
2. 金额使用适合精确货币计算的存储方案，不使用浮点数作为业务金额来源。
3. 身份证号码按文本保存，不得按数字保存，保留末位 `X`。
4. 对自然月、主体、员工、批次类型、状态和规则生效期间建立必要的唯一约束和索引。
5. 历史工资结果必须保存快照，不能仅通过关联当前员工表来解释历史结果。
6. 导入批次必须能追溯原始文件、模板版本、工作表、原始行号、字段映射、校验状态和错误信息。
7. 规则表必须支持城市、生效开始日期、生效结束日期、社保险种、公积金比例和基数上下限。
8. 第一版不实现个税公式，但要为外部税务字段留出明确的来源/空值/警告表达方式。
9. 先定义规范化领域模型，再设计数据库；不要直接把四个 Excel 宽表复制成数据库表。
10. 真实输入 Excel 不在仓库中时，用最小自造 fixture 和测试数据验证表结构及约束。
11. 不修改或覆盖用户已有的无关改动，不提交 git commit，除非用户另外明确要求。
